# Conjecture proofs

Proofs and disproofs of conjectures taken from recent mathematics papers and from
problem lists. Every result here was found with AI agents, checked by the Lean 4 proof
assistant against Mathlib, and then reviewed for whether the Lean statement says what
the source says.

The repository is updated as new results are checked and reviewed.
[HISTORY.md](HISTORY.md) records every addition, correction and reclassification.

> **Status of this work.** These results have not been reviewed by any mathematician.
> Every proof has been checked by the Lean proof assistant, so I am confident each one
> proves the statement written in Lean. I am less sure of two things: that nobody solved
> these before, and that each Lean statement says exactly what the original authors
> meant. If you find a mistake or know of earlier work, please open an issue and I will
> correct the record.

## What these results are, and what they are not

- **They are unrefereed.** Nothing here has been through peer review.
- **Most of them are small.** All but one are conjectures printed in papers of 2025 and
  2026, usually stated by the authors after computer experiments. They are not famous
  problems. The exception is a partial result on a problem from the Kourovka Notebook,
  an established list of open problems in group theory; that problem is still open.
- **"Full resolution" means the statement as printed.** Where a result depends on how a
  sentence of the source is read, its page says which reading was taken.
- **"New" means that no earlier solution was found**, after the searches described in
  [docs/prior-art.md](docs/prior-art.md). It never means certain. Results that turned
  out to have been done before are kept, in their own table, and credited to whoever
  was first.
- **A machine check is a check of the proof, not of the statement.** Lean guarantees
  that the proof proves the Lean statement. Whether the Lean statement is the source's
  statement is a judgement, made by reading both side by side.

## How these results were produced

The proofs here were found and written by Anthropic's Claude Fable 5.2 (an AI model),
through agentic work in Claude Code. Each attempt to prove or disprove a conjecture is
written in Lean; a separate agent then compares the Lean statement with the original
source and searches for any previous solution. A fixed checker script, which the agents
cannot change, decides whether a proof is accepted. The checker, the rules and the pages
in this repository, the harness as a whole, were closely directed by me and written by
Claude. I set up the project and the harness, decided what counts as a result, read the
results, and decided what to publish. So far I have studied two of these proofs closely
enough to explain them myself ([Ku's Conjecture 5.4](conjectures/ku_kinarow_conj54/) and
the [cycle formula](conjectures/cycle_consistency_probability/)); more will follow.

## How each result is checked

1. **The statement** is written in Lean as a definition `Claim : Prop`, in a file of its
   own, `Statement.lean`, short enough to be read against the source.
2. **The proof** is a Lean theorem `result : Claim`, in `Proof.lean`.
3. **The checker**, [`tools/check_lean.sh`](tools/check_lean.sh), compiles both with a
   pinned Lean and Mathlib, confirms that `result` proves exactly `Claim`, walks the
   proof to find every axiom it rests on, accepts only the three standard ones
   (`propext`, `Classical.choice`, `Quot.sound`), refuses `sorry` and `native_decide`,
   and replays the proof in Lean's kernel. Its output is quoted on each result's page.
4. **A review**, by a session that did not write the proof, compares `Statement.lean`
   with the source, hypotheses and all, and searches for an earlier solution.

Details, limits, and what the checker's output means: [docs/verification.md](docs/verification.md).

## Check them yourself

```bash
git clone https://github.com/marcosmartinsalvador/conjecture-proofs
cd conjecture-proofs
./setup.sh                                   # Lean 4.36.0 and Mathlib (about 10 GB)
export PATH="$HOME/.elan/bin:$PATH"
tools/check_lean.sh kourovka_20_52_class_deficiency      # one result
lake build                                   # or simply build everything
```

`tools/check_lean.sh <folder>` should print `ACCEPTED` with the same statement and proof
fingerprints as on that result's page.

## Corrections

If a proof is wrong, a statement misreads its source, or a result was done before:
please [open an issue](https://github.com/marcosmartinsalvador/conjecture-proofs/issues).
Corrections and withdrawals are recorded in [HISTORY.md](HISTORY.md). A result that
turns out to be wrong is marked withdrawn, with the reason; it is not deleted.
