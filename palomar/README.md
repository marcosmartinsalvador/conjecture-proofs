## One thing to settle before submitting

**As this repository stands, Palomar will refuse a submission made from it.** Its rules
say that every `.lean` file in the submitted repository must start with `module`, not
only the files of the package. The 49 Lean files under `conjectures/` do not, and
cannot while the checker here stays as it is: `tools/check_lean.sh` refuses files that
use the module system. Palomar scans the whole repository before it builds anything.

Two ways out:

1. **Submit from a small repository that holds only these packages** (and a copy of
   `LICENSE` at its root). Each folder here is self-contained, so it can be copied
   there as it is: put the three folders at that repository's root, or keep them under
   `palomar/`. This repository stays the home of the results and of the checker.
2. **Port every Lean file in this repository to the module system.** That needs a
   change to the checker, and every result's fingerprints change.

## What is in a package

| File | What it is |
|---|---|
| `Challenge.lean` | The statement: the text of `conjectures/<folder>/Statement.lean`, then `theorem result : Claim := by sorry`. This is the file a reader audits. It imports only Mathlib. |
| `Solution.lean` | The same statement, then the text of `conjectures/<folder>/Proof.lean`, which ends with `theorem result : Claim`. |
| `comparator.json` | Tells `lake comparator` to compare the theorem `result` in the two files, allowing only the axioms `propext`, `Quot.sound` and `Classical.choice`. |
| `formalization.yaml` | Palomar's metadata: author, sources, subject codes, how the proof was produced and reviewed. |
| `README.md` | The account in words: what is proved and what is not, the source's statement, how the Lean statement reads it, the idea of the proof, whether it is new, and how it was produced. |
| `lean-toolchain`, `lakefile.toml`, `lake-manifest.json` | Lean 4.36.0 and Mathlib v4.36.0 (commit `fc4f59e577fe`), the same versions as the rest of this repository. |

The Lean text was copied, not rewritten. Only the import lines differ: Palomar requires
the `module` header, so `import Mathlib` became

```lean
module

public import Mathlib

@[expose] public section
```

In `delta_primitive_two_primes` one sentence of a comment, which pointed at files that
are not in the package, was reworded. Nothing that Lean checks was touched.

**The proofs were generated by Claude Fable 5.2, an AI model made by Anthropic.** Each
package's `formalization.yaml` and `README.md` say so.

## Checking

```bash
./setup.sh                          # at the repository root: installs Lean
export PATH="$HOME/.elan/bin:$PATH"
palomar/verify.sh                   # all three; or: palomar/verify.sh <folder>
```

`verify.sh` needs Linux and `bwrap` (bubblewrap, the sandbox `lake comparator` uses).
For each package it checks that

1. every Lean file has the `module` header and is within Palomar's size limits;
2. the Lean text is the text of `conjectures/<folder>/Statement.lean` and `Proof.lean`;
3. `lake comparator` accepts it, with Lean's kernel and the two independent kernels
   shipped with Lean (NanoDa and con-ron), as the registry runs it.

To run the comparison alone, in a package folder: `lake exe cache get && lake
comparator`. It should end with `Your solution is okay!`.

One more check was made when the packages were built, and is not repeated by the
script: the original `conjectures/<folder>/Proof.lean`, compiled as it is, was exported
and given to `lake comparator --solution-from-export` as the solution to each
`Challenge.lean`. All three were accepted. So each `Challenge.lean` states exactly what
the proof accepted by this repository's checker proves.

## Submitting

One submission per package, on [the submission form](https://submit.palomar-registry.org/),
signed in with the author's own GitHub account. For each one the form needs:

- the repository, and the full commit SHA to be reviewed (`git rev-parse HEAD`);
- the project directory: the package folder, for example
  `palomar/kourovka_20_52_class_deficiency`;
- the Comparator configuration: `comparator.json` in that folder, for example
  `palomar/kourovka_20_52_class_deficiency/comparator.json`.

Palomar also asks for credible research interest. The Kourovka result is on a problem
from an established list and is a partial answer. The other two settle conjectures
printed in single recent preprints, which may count for less there.
